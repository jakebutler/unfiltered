# Private research S3 port contract

This slice supplies an official SDK v3 port for the existing `BucketPrivateObjectStore`, not a public upload/download endpoint. Existing capture/report authorization and per-chunk consent checks remain required. It is not integrated into the running research server by this slice; local-store fixtures remain unchanged. No native AWS claim follows from command-handler mocks.

The approved retirement protocol uses **no DeleteObject**. Available bytes use a single bounded `PutObject` with `IfNoneMatch: '*'`; retirement is an authoritative unconditional overwrite of the same key with zero bytes and `state=retired`. The marker is permanent. [AWS conditional-write semantics](https://docs.aws.amazon.com/AmazonS3/latest/userguide/conditional-writes.html) and [strong consistency](https://aws.amazon.com/s3/consistency/) support this inference: if create commits first, retirement replaces it; if retirement commits first, conditional create cannot replace the marker. Success is followed by authoritative HEAD reconciliation. An unknown write/retirement outcome is thrown, never automatically retried; the caller must reconcile that exact attempt.

Only a **fresh, never-versioned general-purpose bucket** is supported. Suspended versioning is rejected, because old versions can retain withdrawn bytes. No lifecycle expiry, replication, Object Lock, restore job or backup may remove markers or reintroduce old raw bytes. Startup must inspect versioning, lifecycle, replication, lock, encryption, public-access blocking and ownership; a missing permission/unknown/malformed response fails before writes. The template denies destructive/drift configuration operations. Approved control-plane changes still require stopping all writers and requalification; bucket policies are not an atomic transaction with configuration reads.

Inputs are a secret-free fixed bucket/region/account, exact KMS key ARN and research object namespace, plus an **explicit credential provider**. There is no endpoint override, default credential discovery, URL/presign method, ACL or multipart upload. SDK retries are disabled (`maxAttempts: 1`); each operation and returned body has a bounded deadline. Logical keys retain the existing server-chosen `research/session/attempt` contract and map below the fixed namespace. IAM is limited to that dedicated bucket/prefix and key. Unconditional overwrite is trusted retirement authority: IAM does not independently prove that its body is zero bytes.

Available writes must match declared SHA256/MIME and the existing 8,000,000-byte segment envelope. They send an S3 SHA256 checksum and exact SSE-KMS/owner headers. HEAD validates content length, strict state/hash metadata, full-object service checksum, key/encryption and non-versioned/non-replicated/non-expiring state. An ETag is an opaque race fence, not the content hash. GET binds `IfMatch` to the validated HEAD, checks exact single-range response metadata, and streams at most that range in bounded chunks. Cancellation/deadline stops the SDK request/body; truncation/overflow fails. Already delivered bytes cannot be recalled; existing gateway consent checks prevent later chunks after withdrawal. [PutObject](https://docs.aws.amazon.com/AmazonS3/latest/API/API_PutObject.html), [HEAD permissions/checksums](https://docs.aws.amazon.com/AmazonS3/latest/API/API_HeadObject.html), [GET range/condition contract](https://docs.aws.amazon.com/AmazonS3/latest/API/API_GetObject.html).

Offline acceptance must cover both create/retire race orders, occupied/retired keys, uncertain writes with no retry, forged metadata/checksum/encryption, ignored/wrong ranges, versioning/lifecycle/replication drift, foreign key/configuration, bounded truncation/overflow/cancel/deadline and no credential/network discovery. Native S3 conditional-race/retirement, key/IAM/network behavior and consent-qualified deployment remain later explicit gates. Clinical Medplum storage stays separate; synthetic/PHI/provider gates in the AWS baseline remain unchanged.
