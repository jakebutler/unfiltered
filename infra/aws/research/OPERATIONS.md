# Independent AWS research package

This slice reuses the research capture/report gateways, native lease/admission and object contract in an independent static/Node container. It binds three HTTPS identities from `infra/aws/examples/research.json`; it does not inherit the hosted Vercel/Convex/R2 identity. Node22 and the existing locally accepted self-hosted Convex image are pinned; metadata persists separately from S3 recordings. Model/speech defaults are off; the private optional configuration path is described below. No AWS resource or provider is contacted by packaging, synthesis or the offline checks.

## Build and inspect offline

Use the pinned Node22 executable, a 1 GiB heap and the coordinated serial slot. Supply the existing accepted Linux FFmpeg binary and its exact license; the public pin is `infra/aws/examples/research-ffmpeg.json`. The package checks both hashes and ELF architecture and copies the license. It does not download a binary, install dependencies or read environment files. The AWS app supports the manual capture/publication/revocation workflow; live reasoning/speech qualification and activation remain separate. Source receipts bind the reused handlers and frozen Convex deployment sources.

The resulting Docker build context contains no dependency installer or cloud entrypoint. `backend-source` holds the exact Convex/function source and lockfile for a later explicit private-backend deployment. `compose.yml` provides pinned independent local services; backend ports bind loopback. Its explicit interpolation variables are documented in the file. No container or VM was started for this implementation.

The runtime file is private mode0400 owned by UID1000. Its typed shape is in `config.ts`: gateway secret, new finite allocation ID, explicit `ec2-imdsv2`, exact bucket/account/region/KMS/namespace, reduced byte bounds, fresh recovery identity and `liveProvidersEnabled:false`. S3 startup qualifies the existing storage controls through `S3PrivateBucketPort.open`. Credentials come exclusively from a bounded fixed-endpoint IMDSv2 exchange and exact stack role; no IMDSv1, endpoint override, profile or default-chain fallback exists. The application uses host networking for hop-limit1 IMDS. It exposes only port8080 through its guarded origin contract.

The 20-resource template includes the existing retained private S3 bucket/policy, named runtime role, private Node, retained encrypted root disk, a separate retained encrypted20GiB metadata volume with exact AZ/attachment, Convex3210/site3211 target routes and TLS for three named hosts. Inputs include the existing VPC/subnets, explicit viewer CIDR, qualified AMI, exact image digest, KMS identifiers, secret suffix, certificate and separately initialized metadata filesystem UUID. Node/subnet/volume must share the explicit AZ. The operator initializes and mounts the supplied volume once through a separately qualified procedure; bootstrap never formats, creates the metadata directory or falls back to the root filesystem. Replacement reattaches the retained volume; preserve its CloudFormation identity rather than creating a blank replacement.

On each boot, one shared `unfiltered-research-runtime.service` oneshot reloads the same exact secret ARN before either normal service gate. It creates the private volatile directory, removes any stale runtime, retrieves into a private temporary file with one AWS attempt/connect5s/read10s/overall20s, bounds the file to32768 bytes, sets UID1000/mode0400, and renames atomically. Failures leave no runtime and prevent both dependent units starting; private content is never logged. No credential/config-file fallback is used. A changed secret still fails the retained READY runtime digest until separately accepted. The oneshot remains successful for that boot. For deliberate runtime rotation, stop both normal units, restart this oneshot, validate and separately accept the new READY before restarting normal units; no hot rotation is supported.

Every normal backend and application start runs the same `/opt/unfiltered/startup-gate.mjs --check-start`. It observes the exact `/srv/unfiltered` mount with `findmnt`, filesystem UUID and underlying EBS disk serial with `lsblk` before reading admission files. The observed serial must equal the template's exact volume ID without its hyphen. Wrong or absent mount, profile/namespace/image mismatch, stale runtime/recovery identity, missing READY, any SEALED/RECOVERY-PENDING/RESTORE-SEALED marker, or a restored Convex marker denies both units. The app launcher repeats the persisted binding check before S3 initialization. The AMI must have Node22, GNU timeout and fixed `/usr/bin/findmnt` and `/usr/bin/lsblk`; no discovery or root fallback is supplied.

On the verified volume, root creates `/srv/unfiltered/admission` mode0755 and root-owned JSON files mode0644 (public digests/identities only). `METADATA-IDENTITY.json` is an exact copy of `/opt/unfiltered/research-binding.json`, which includes schema1, stack/profile/namespaces, pinned image, volume ID and UUID. READY is root-written only after accepted private initialization or recovery proof, with exactly `{schema:1,state:"accepted-fresh"|"accepted-reconciled",binding:<same binding>,recoveryIdentity:<fresh runtime recovery identity>,runtimeHash:<runtimeHash(raw private runtime JSON)>}`. Import `runtimeHash` from `startup-gate.mjs` to compute the digest; do not print or persist the private runtime fields in admission. Preserve binding property order. Updating credentials, gateway signing identity or named allocation changes the runtime digest and requires fresh acceptance. No tool here emits READY automatically.

AMI/bootstrap credentials, private-node HTTPS egress, DNS and native initial operator/JWT setup are later qualified prerequisites. Stop both normal units before modifying metadata or admission; no hot recovery is supported. For first initialization/quarantine use only a separately named backend, the same pinned image and verified metadata mount, `--publish 127.0.0.1:3310:3210 --publish 127.0.0.1:3311:3211`, with normal units stopped, provider egress disabled and no public forwarding. Perform exact frozen-source deploy and quarantine locally through those private ports, then stop that backend before normal admission. This is an explicit recovery path and never starts the app. Local proofs must use their own namespace/ports; existing3210/3211 services are untouched. The supplied Compose backend is also loopback-only; it is not a replacement for the AWS systemd mount gate. No automatic traffic reopening is supplied.

## Optional qualified provider configuration

The public deployment manifest remains provider-off. Private runtime configuration defaults to `liveProvidersEnabled:false` and all `providers` entries disabled. Supplying keys alone enables nothing; there is no environment/default-key lookup or endpoint override. A later separately authorized capability activation must explicitly set `liveProvidersEnabled:true`, provide typed `providers` entries and private `credentials`, and obtain a new READY digest after native qualification. This repair activates no provider.

Interview uses `{enabled:true,qualification:"root-reviewed-research-interview",model:"qwen3.8-max"|"glm-5.3-flash",timeoutMs:100..15000,maxRequestBytes:1..64000,maxOutputTokens:1..512}` and explicit `digitalOceanKey`. Analysis reuses `analysis-config.ts`: provider `digitalocean`, model `qwen3.8-max`, qualificationId `DO-V1`,1..8 unique named reservations with finite input/output bounds and expiry, optional bounded timeout/request sizes, and explicit `digitalOceanKey`. FFmpeg is always the packaged pinned binary; a private path override is rejected. Speech uses `{enabled:true,qualification:"root-reviewed-continuous-research-speech"}` and explicit `deepgramKey`/`elevenlabsKey`. Native named allocation, interview/speech policy, speech grant and operation reservations remain mandatory at dispatch. Existing handlers/adapters enforce those gates; this composition neither creates policy nor refunds allowance. Other provider/model/endpoint fields are rejected. Live qualification must prove actual finite policies/reservations and exhaustion before activation.

## Sealed metadata checkpoint and recovery

Stop both normal systemd units, application writers, all backends sharing the directory, and cleanup workers; inspect actual stopped containers before using the attestation flag. These commands never stop a container themselves. Use a new mode0700 work directory, a private exact32-byte key and a private identity JSON with `profileHash`, pinned `convexImage`, `metadataNamespace`, `objectNamespace`, and `recoveryIdentity`. Identity order must be preserved between sealing and restoration.

```sh
node infra/aws/research/recovery-cli.mjs seal --metadata /absolute/stopped/convex-data --archive /absolute/private/checkpoint.ufrs --key-file /absolute/private/recovery.key --identity /absolute/private/identity.json --receipt /absolute/private/backup-receipt.json --writers-and-backend-stopped
node infra/aws/research/recovery-cli.mjs restore --admission-directory /srv/unfiltered/admission --archive /absolute/private/checkpoint.ufrs --target /absolute/private/new-convex-data --key-file /absolute/private/recovery.key --identity /absolute/private/identity.json --receipt /absolute/private/restore-receipt.json --writers-and-backend-stopped
```

The restore CLI first writes SEALED and removes READY in the explicit trusted admission directory; archive failure leaves normal starts denied. The AES256-GCM archive is bounded to64MiB of volume files, authenticated completely before any destination writes, rejects symlinks/hardlinks/path traversal, requires an empty new target and writes `RESTORE-SEALED.json`. It never archives or restores S3 raw objects, rewrites bucket policy, or removes permanent retirement markers. Keep traffic sealed and restore on an isolated backend with provider egress disabled. A metadata checkpoint may precede later withdrawal; it is never permission to restore old consent or report grants.

`researchRecovery:quarantine` is an internal-only native mutation, guarded by the explicit temporary `RESEARCH_AWS_RECOVERY_IDENTITY`. `reconcileRecovery` in `recovery.mjs` invokes it in25-row pages, at most64 pages per turn, with a durably saved resumable checkpoint. It disables restored operators, removes auth sessions/refresh/verification tokens, revokes invitations/shares/viewer sessions, withdraws capture consent, removes restored source text/DOM/derived findings, disables speech/interview policies and expires old allocations/leases while retaining counters and `workStarted` history. Every current/historical media key returned by quarantine is permanently retired through the same qualified S3 port and read back before advancing. Unknown outcomes preserve the pending key and sealed checkpoint. No old allowance is refunded or reused.

Reconciliation ends at `quarantined-awaiting-fresh-identity-and-native-qualification`, never READY. Rotate backend admin/JWT/gateway identities, provision a new named operator and a new finite allocation, then qualify direct access denials and permanent fences against the actual restored backend/storage before any separate acceptance of reopening. Stop the private recovery backend, preserve quarantine/fence history, and remove sealed markers only after those native proofs; write the exact new READY last. Deleting markers alone is not acceptance. Old shares, sessions and publications are intentionally unavailable after conservative restore; fresh consent/report review/publication must be explicit. No generic restore of withdrawn raw bytes is supported.
