# S3 browser voice: implementation evidence and device test plan

2026-10-09. Offline implementation evidence only. No microphone grants, clinical audio, provider requests, server restarts or live browser speech tests were performed for this frontend change. Provider enablement and actual desktop/mobile acceptance belong to the coordinator.

## Implemented boundary

- Optional voice controls use the service's `voice.available` flag. The microphone requires the visible transcription consent checkbox and an explicit Start recording gesture. Unsupported browsers or permission denial leave typing available.
- Audio is microphone-only with echo cancellation, noise suppression and automatic gain control requested. Browser support for these constraints is not guaranteed. No raw audio is persisted by the browser app; only current processing frames exist in memory.
- The actual `AudioContext.sampleRate` feeds a stateful area-weighted resampler. 16, 32, 44.1, 48 and 96 kHz inputs are tested for exact 16 kHz output counts and invariance across input chunks. The supported input range is integer 16–192 kHz; this is format support, not microphone-quality qualification.
- The WebSocket uses the same origin and `/api/clinic/speech/input` with no query. A fresh STT attempt UUID is sent in the first start message with session, prompt and revision. No PCM is sent until valid ready. Every reconnect is explicit and gets a new STT ID; no raw audio is replayed.
- Capture obeys the server's positive integer `maxCaptureMs`, at most 60,000 ms. PCM is signed 16-bit little-endian mono at 16 kHz, bounded by returned duration × 32 bytes/ms, at most 1,920,000 bytes. Each frame is at most 16,384 bytes; queued socket bytes plus the next frame must stay at or below 64,000. Send rate cannot exceed elapsed time plus two seconds. Worklet posts 1,024-sample mono blocks.
- Finish turns tracks off immediately, flushes the final partial worklet frame and sends one finish control. Flush is bounded to 200 ms; failure interrupts honestly. The complete finish/drain window is bounded to 5,000 ms from the user's finish action. Stop interrupts immediately. Listeners, tracks, processor, audio context, socket and timers are disposed on terminal events, scope changes, page hiding, pagehide and unmount; late permission results are disposed.
- Interim recognition is labeled separately. Finalized words use the same composer as typing. Interruption promotes available provisional words to editable unsent review with a missing-words warning. No recognition or finish event sends an answer. Only explicit Send reviewed answer saves via the existing normal/adaptive endpoint with `channel: confirmed-transcript`.
- One stable answer request ID is distinct from all speech attempt IDs. Uncertain saves retain the exact payload and ID, freeze editing/capture and use existing same-request save recovery. Clearing or acknowledged saving creates a fresh answer ID. Existing typed prefix whitespace is preserved. Denied/empty recording does not relabel typed-only words as a transcript.
- Guided choices and structured fields, including the four frozen PHQ items, keep their original controls and disable recording. Read-aloud remains possible for authorized current prompt/reply text.
- Read-aloud sends only server-resolved source references to the same-origin output route. Source text longer than 1,200 characters is not silently truncated. Output must be audio/mpeg and nonempty, at most 600,000 bytes, with a 30-second preparation deadline.
- When `MediaSource.isTypeSupported('audio/mpeg')` returns true, read-aloud appends incoming MPEG chunks to one SourceBuffer, serializing every append through `updateend`. The first completed append starts one playback attempt while later response chunks continue arriving. End-of-stream is signaled only after the complete response and final append. There is at most one pending append and no duplicate JavaScript chunk cache; the same bounded media buffer remains for explicit autoplay retry/replay. The MPEG MIME type and append lifecycle follow the [W3C MPEG byte-stream definition](https://www.w3.org/TR/mse-byte-stream-format-mpeg-audio/) and [Media Source Extensions specification](https://www.w3.org/TR/media-source-2/).
- **Only browsers without MPEG MediaSource support use the bounded Blob fallback, which waits for the entire response before playback.** The UI states this per browser. It may miss the five-second first-audio target even if server streaming is fast. A supported streaming path that fails to append/decode stops with an error; it does not silently refetch or switch to Blob.
- A blocked autoplay result exposes Play audio on the existing media buffer/Blob; Play again reuses it too. Neither calls the provider again. Audio is cached only in memory and its object URL is revoked on stop/scope change/unmount. Local synchronous pause and abort are attached before source attachment and async fetch/play. Old scope/generation results cannot restart playback. Abort disposes pending appends/readers/listeners; a 30-second deadline begins before fetch and covers source opening, the entire response and append completion, even if playback has started. Successful full receipt cancels that download deadline, so later explicit cached replay is not a new provider operation.
- Local RMS voice detection uses threshold 0.018 for at least 30 ms and stops playback synchronously on sustained voice, including playback beginning mid-utterance. Offline block tests signal within 64 ms at tested rates; **this is not measured browser barge-in latency**. Echo behavior, main-thread scheduling and hardware still require device tests. A Stop audio control remains available.
- Connection setup is bounded to 15 seconds after microphone/worklet initialization. Permission dialogs remain under browser/user control and can be canceled via Stop microphone. An eight-second still-working message appears while connecting or preparing playback, without another provider request.

Eighteen additional audio lifecycle tests cover first-chunk playback before response completion, append ordering, abort while opening/appending/reading, stale events, SourceBuffer errors, source closure, no failure fallback, pre-response and in-response deadlines, MIME support detection, output bounds and retained response reuse.

## Coordinator's manual desktop and mobile qualification

Use synthetic content only and a separately authorized speech-enabled environment. Test desktop Chrome/Safari and a real mobile browser, with at least 20 successful representative turns per device class plus all failure cases. Preserve the tested URL/origin and record browser/device, input device, actual sample rate and whether echo cancellation is supported. Record `MediaSource.isTypeSupported('audio/mpeg')` and the actual streaming/fallback path on every device.

1. Confirm unavailable mode truthfully shows typing. With voice enabled, verify no microphone permission or WebSocket before the checkbox plus recording gesture. Deny permission, revoke it while recording, and cancel while the permission dialog is pending; typing must survive and any late stream must close.
2. Type a prefix containing newlines; record negation, medicine names, units and amounts. Check distinct interim/final wording, Finish, editable review, same draft after switching to typing, and no clinical save before Send reviewed answer. Inspect the resulting source's confirmed-transcript label and exact reviewed text.
3. Disconnect during setup, speaking and final drain. Stop waiting before a delayed final. Check provisional words remain unsent with the missing-words notice, no auto reconnect, no stale segment overwrite, and explicit reconnect has a new STT ID but unchanged answer ID. Check the last syllable at Finish and the strict minute/shorter-lease cap.
4. Simulate an uncertain normal and adaptive answer-save response. Verify microphone/send editing are frozen; the visible same-save retry resolves the original ID without a duplicate answer or automatic interpretation retry. Existing S2 stop/status/guided/correction/prior-receipt flows must still work.
5. Open PHQ items and structured guided fields. Recording must remain off and exact answer choices usable. Read-aloud must correspond to the current authorized source and no past patient text may be submitted as TTS input.
6. Listen, stop during fetch, stop during play, change topic/revision, hide the page, navigate away and return. No stale audio may resume. Block autoplay and confirm Play audio uses the already downloaded clip, with exactly one output request. Explicit cached replay must also make no request. A new Listen action after Stop is a deliberate new attempt.
7. Record while read-aloud plays; speak over it using both speakers and headphones. Measure user voice onset to actual output silence, including speech already active when playback begins. Test Stop audio by keyboard/touch. Target under 500 ms; do not infer this from the offline VAD test.
8. Background/lock mobile, change Bluetooth/headset, rotate, show keyboard and interrupt phone audio. Verify mic indicator and tracks end, transcript remains editable, long text does not overflow at 390×844, focused review field is usable and all controls have visible keyboard focus and accessible names.
9. Measure end of utterance to first usable text, explicit Listen to first audible sound, and final review readiness. Target p95 at most five seconds and local feedback within one second. **Measure actual first audible sound separately for incremental MediaSource playback and full-clip Blob fallback, not provider first-byte latency.** A failed latency target remains a limitation; do not automatically generate another clip.
10. Exercise slow socket buffering, invalid/oversized events, unavailable output, empty output and the 30-second deadline. UI must preserve draft text, stop resources, state the failure and leave typing/stop controls available without silent retries.


## Natural conversation addition

The approved natural voice flow is now wired alongside dictation. Start voice conversation uses the existing fictional-audio checkbox and a gesture. The controller starts bounded input before read-aloud; final speech plus 600 ms of quiet requests finish; only a clean completed drain with no provisional words automatically saves an `unreviewed-transcript`. Duplicate final/completion events cannot dispatch another save. A durable acknowledgement precedes the single interpretation attempt, and the next capture uses the newly acknowledged prompt/revision and a new answer ID. Speech failure, ambiguous save/inference, a capture limit, 15 seconds of quiet after playback, PHQ/structured choices, review, identity loss and page hiding pause automatic continuation. Stop/typing preserve available text; playback blocking retains the same audio for explicit Play audio. Dictation still requires explicit reviewed sending.

Twenty-four event-clock/presentation tests cover these transitions, including stop during a submitted save, duplicate completion, endpoint cancellation, clean versus provisional drain, stale scopes, one next capture after acceptance/interpretation, uncertain recovery without replay, PHQ/review pauses, immutable unreviewed source labeling, and the guided symptoms positive/free-text path beside None/no. Clinic build/typecheck pass. These are deterministic tests, not rendered or microphone acceptance.

An isolated development page is available at `/voice-fixture.html` on the existing Vite server. It refuses production mode, is not imported by the clinic or included in the production build, and contains no clinic/provider fetch or WebSocket path. Its explicit Run button sends an oscillator through the actual AudioContext → clinic AudioWorklet → PCM resampler → in-memory sink, reports real input rate/counts and exact expected PCM bytes, then closes resources. It asks for no microphone. This fixture has been typechecked but **has not been run in a browser by this agent**. It validates the audio graph only, not the authenticated socket/model/handoff flow; the coordinator's separate synthetic integration fixture and real-device matrix remain required.

Still to qualify on a real device: reopening/resuming capture automatically under retained browser activation; real endpoint and drain accuracy; recognition of negation/medical values; prevention of speaker echo being saved as patient speech; local barge-in; actual browser MPEG append/decode; microphone revocation/background/Bluetooth; and the complete five-second latency target including next-capture readiness.
