## Self-audit

1. **Integrated late.** Too many extraction changes were evaluated outside the final handler, persisted draft, resumed UI and handoff. This deferred discovery of route-context and navigation problems. Complete vertical behavior should have been the primary test from much earlier.
2. **Over-optimized the model representation.** Compact aliases reduced wire size but introduced global field/item/source cross-reference work. AF85 actually emitted the Metformin strength twice: a corrected known value and an inappropriate whole-field negative, producing duplicate-sparse-slot. An earlier claim that its Vitamin D field identifier belonged to Metformin was disproved by independent inspection of the exact frozen request and is withdrawn. Alias complexity remains a general design concern, not the established cause of this specific failure. More prompt metadata would add another lookup layer. Readability and correctness matter more than minimizing already bounded request bytes.
3. **Too many small experiments.** Repeated one-case probes, followed by a new freeze and review, provided weak generalization evidence and consumed orchestration time. The full representative batch produced more useful information in seconds of inference than many earlier isolated probes.
4. **Proof machinery became work of its own.** Immutable evidence, no duplicate provider dispatch, privacy and authorization checks were justified. Repeating source inventories, exact reviewer receipts, temporary allocation setup and deployment roundtrips for small changes added disproportionate friction. We should preserve automatic checks while reducing hand-produced artifacts and root-agent handoffs.
5. **Operational test setup obscured product usability.** Short readiness windows and tool delays made normal UI work fragile. Repeated OFF/config deployments consumed finite test windows. A test that only works through developer fixtures does not establish that Jake can operate the product.
6. **Diagnosed from incomplete evidence.** AF74 and AF85 both attracted incorrect initial explanations before the exact frozen request, raw output and first decoder failure were inspected together. Those explanations were withdrawn. That check must precede a targeted fix; otherwise even careful validation can validate the wrong hypothesis.
7. **Orchestration focused too narrowly on the next gate.** I should have challenged complexity and assessed end-to-end delivery sooner, rather than treating each local validation gate as the natural next unit of progress. Strong independent review caught real defects, but review effort must be sized to risk and grouped around meaningful changes.
