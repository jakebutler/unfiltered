# S5 browser capture slice

October 9, 2026. Static implementation only. No tests, typechecks, builds, browser sessions, services, VM, Convex push, real microphone/camera/screen capture, hosted provider, cloud or secret operation was run for this slice. The root coordinator owns execution scheduling and acceptance.

## Implemented

`apps/research/src/capture-browser.ts` owns the browser recorder lifecycle. Every retained source combines all chunks from one complete MediaRecorder run with a 15-second target ending in `onstop`. A fresh recorder begins the next source. Individual `dataavailable` timeslices are not uploaded or claimed independently decodable. Browser-supported allowed MIME selection, 500 kbps requested video/64 kbps requested audio, 8 MB hard accounting, the original capture deadline, two pending complete containers per modality, and one shared six-slot budget for live and pending containers bound local work. The aggregate slot admission reserves at most 48,000,000 bytes of container/chunk payload across all modes; hashing can temporarily add one bounded 8 MB ArrayBuffer per modality (24 MB total). Browser encoder/network buffers are browser-owned and are not a process-RSS guarantee. Bitrates are requests, not size guarantees. Camera records video only; microphone records audio only; screen capture explicitly requests no tab/system audio. Microphone, camera and screen have simultaneous independently controlled recorders on the same backend capture clock, with separate per-mode sequence/interval/source identity; DOM can accompany all three. No camera or screen audio track is requested, so audio is retained only by the microphone recorder. `CaptureControls.microphoneStream()` exposes the already active microphone stream for future voice coordination; consumers must detach without stopping recorder-owned tracks, and voice integration must not create a second raw-audio save.

Permission denial keeps text usable and records a gap. Late permission results after stop are closed without starting a recorder. Track ended/mute closes devices. Question changes rotate the container so future sources name the new question. Pause/finish calls browser stop before the conversation mutation, finalizing the last container while new admission remains open. Page hide and unmount close all tracks/listeners immediately and discard unsent local content. Selective consent withdrawal closes/discards only its modality or DOM bridge; remaining permitted modes continue. Global pause/end closes all modes together. Buffer backpressure records a capacity gap and stops the affected track, preserving text and other tracks instead of silently dropping containers. Media transport has a 65-second client wait bound; this is not proof that an unknown server write failed.

`ResearchCapture.tsx` exposes separate optional consent for microphone, camera, screen and controlled DOM, disabled-by-default initial interview consent, separate per-track start/stop, end-all, text fallback, and original-result recovery. Permission controls remain accessible after pause/completion. Selective capture withdrawal does not change required text storage/analysis or disable saved-answer actions. Existing client-sharing fields are preserved; withdrawing the matching modality also clears its sharing flag.

All device modalities share a serial PUT queue matching the server’s single-upload cap; concurrent recording does not dispatch overlapping writes. A waiting upload starts its 65-second HTTP wait only when dispatched. Admission is rechecked against the modality’s consent/generation immediately before dispatch. Withdrawal/page hide cancels waiting work and releases its retained body/slot without a PUT; dispatched unknown results keep normal explicit reconciliation semantics.

PUT/POST use the same-origin `/capture/media/:id` facade, with `X-Research-Participant` in headers and raw capped Blob on PUT. Browser fetch supplies Blob Content-Length; the browser must never try to set the forbidden header manually. Every reservation retains its exact UUID/descriptor/body. An unknown PUT stops that modality and keeps its in-memory source; independent permitted modalities can continue. Explicit recovery first POSTs reconciliation; only an `available` receipt or a gateway-fenced `reserved` successor proceeds. No silent ambiguous retry, no new logical reservation for recovery, no capability in query/path/referrer.

DOM opens only the pinned study prototype and forwards `acceptPrototypeMessage`-validated actual source/origin/challenge/schema events. The capability never reaches the prototype. The operator separately authorizes the pinned exact origin and opaque component IDs. A fresh challenge starts/reconnects a generation with backend nextSequence; old matching connections are disconnected first. Connected is stored before the UI reports connected. Each event retains an original request for explicit unknown-result replay. Queuing is capped at 25; backlog stops the listener instead of accepting indefinitely. Stop/pause/end/withdraw/page hide sends exact-origin `corvo-dom-stop`, removes listener/timers and prevents queued new forwarding. The capture deadline closes DOM. Popup close disconnects the matching generation. Prototype navigation/reload should be explicitly reconnected; the parent does not infer page activity from pixels or third-party DOM.

`CaptureSources.tsx` adds operator private recording playback and paginated DOM/gap inspection. It fetches a capped complete source with live Convex auth in the Authorization header and explicit same-origin fetch referrer policy (required by the server’s Origin-less authenticated browser GET facade), checks Content-Length/body size, and uses a tab-local Blob URL for native audio/video controls. Close, scope changes and sign-out abort reads, pause playback and revoke URLs. No object-store URLs or capabilities are exposed. The gateway protects each streamed chunk. A fully downloaded Blob is already delivered bytes; server revocation cannot recall it. The operator UI refresh removes revoked rows, and closing releases the local copy; this is not a remote wipe guarantee. Source/question IDs, modality/interval/state and masked event/gap provenance remain inspectable.

## Remaining practical limits

Pending source bytes and DOM event recovery requests are intentionally memory-only. The most recent DOM challenge/origin is retained in sessionStorage solely to disconnect a prior generation before a fresh connection after reload; it carries no invitation capability, event content or raw media. If sessionStorage is unavailable, a conversation pause/resume is the explicit server challenge reset. Reload/close loses unsent bytes; the UI asks participants to keep the tab open while pending. Existing reservations/gaps remain server evidence, not invented available sources. No durable offline media spool is claimed. The original upload recovery/deadline/capacity controls still govern explicit recovery. Separate short complete sources can contain recorder restart latency; their intervals show this instead of claiming a continuous uninterrupted video. The browser's stop callback/device/container behavior and rendered layouts are unqualified until the coordinated checks above. Hosted request/object budgets, concrete bucket guarantees and production deployment remain backend/deployment gates.
