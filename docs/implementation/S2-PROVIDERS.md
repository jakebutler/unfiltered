# Bounded provider access

The local clinic server leaves adaptive interpretation disabled unless `CLINIC_PROVIDER_SETTINGS` names a private absolute JSON file with `adaptiveEnabled: true`, `qualification: "root-reviewed-synthetic-adaptive"`, and an explicit `ProviderBudgetPolicy`. That marker is an operator assertion, not an automated clinical certification. Keep the flag off until the root-reviewed live gold evaluation and API security review pass. `CLINIC_PROVIDER_ENV_FILE` may name the user's private absolute env file; credentials never enter browser settings or the ledger. Existing deployments without these variables continue guided mode.

The configured route is DigitalOcean `qwen3.8-max`, native JSON, 4,096 output tokens, at most 60,000 input-content UTF-8 bytes, with no provider/model fallback or repair request. Provider timeout is at most 12 seconds, reduced by admission time so the combined invocation fits 14 seconds. The durable adaptive operation has its own 15-second interpretation deadline. Very slow admission returns without provider dispatch.

`provider-admission.ts` maintains a FHIR DocumentReference under a separate budget identifier, with conditional creation and version-matched updates. It stores hashed session/request references and bounded usage reservations; no transcript, patient identity, credentials or provider response body. The same request ID cannot be admitted again, even from a different session or a restarted process. Ambiguous writes fail closed and retain any possibly committed reservation. Explicit version conflicts may retry storage reads/updates, never the provider call.

The policy's `account` limits are an allocated deployment allowance within the shared account's credits, not a measurement of all account usage or other deployments. Reserve that allocation in the primary shared usage ledger before enabling it. All instances drawing on the same allowance must use the same Medplum project and stable policy ID. Changing limits under that ID fails closed; a new ID must represent a new explicitly allocated allowance, never automatic replenishment. Separate deployment allocations must fit the shared account balance and cash ceiling.

Requests, inference input bytes/output tokens, speech characters and speech seconds each have deployment and session limits. Every attempt permanently charges its full bound. There is no automatic refund for completion, failure, interruption or uncertain delivery. Minimum concurrency leases cover the bounded transports: 20 seconds inference, 70 seconds transcription, 35 seconds synthesis. Unknown/interrupted work retains its concurrency slot until that deadline. Expiry releases concurrency only. At 1,500 claims or the document size bound, the ledger stops accepting work; no truncation or deletion resets duplicates or spend.

The inference wrapper does not lose or repeat a successful provider result if settling bookkeeping fails; the already reserved maximum stays charged. Speech uses the same admission contract through explicitly enabled Node routes described in [S3-VOICE](S3-VOICE.md). All providers also enforce one active claim per session independently of account concurrency. Speech remains disabled by default until the root's allocation and live qualification.

## Evidence

Nine isolated fault/race tests cover simultaneous claims, restart, duplicate IDs, per-session and deployment exhaustion, unknown/interrupted concurrency, ambiguous writes, policy changes and separate provider dimensions. The native Medplum qualification in `evidence/admission-0ac0834e-4316-4bae-9662-93a32b9cf253.json` admitted exactly one simultaneous claim, denied replay after settlement/recreation, and retained exhaustion across recreated admission instances. It made zero inference or speech calls and spent no provider credit. The independent S2 security review is separate; this note does not imply it has passed.
