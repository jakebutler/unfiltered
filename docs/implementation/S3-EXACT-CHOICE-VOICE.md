# Exact-choice clinical voice mechanics — October 10, 2026

This local slice connects the frozen PHQ-4 block and other fixed guided choices to the existing opt-in voice controller. Speech remains disabled by existing operator configuration unless separately qualified and enabled. No provider call, browser action, clinical content change, hosted enablement, or historical qualification-build rewrite was performed.

The normal voice path starts capture before speaking the current server-resolved question. For a fixed-choice item it reads the complete original question and all ordered labels. Recognition matches a single whole label, allowing only case, outer whitespace and trailing sentence punctuation; numbers, substrings, paraphrases, vague statements, diagnoses and “all zeros” cannot populate PHQ responses.

An exact label creates a local unsaved candidate. The controller starts a separate capture with a fresh request ID and reads a server-generated confirmation containing that same frozen item and selected label. Say `Yes` or `Confirm` to save; say `No` or `Retry` to choose again, `Switch to text`/`Use text` for typing, or `Stop`. The same confirmation and retry controls remain visible. Only explicit confirmation posts a deterministic `/api/clinic/turns` answer using the original option request ID, prompt ID and revision. There is no adaptive proposal or interpretation dispatch for these choices.

The server validates the presented item and revision, the exact offered label, and the explicit confirmation vocabulary. It retains the original option transcript and confirmation transcript as distinct patient sources, with the fixed prompt/confirmation as assistant turns. PHQ item evidence links both patient sources. A control confirmation records its method truthfully as text evidence. Request deduplication and compare-and-swap remain the existing turn handler's responsibility.

Nonmatching clean choice speech is saved through the same durable turn path as `choiceTranscriptOnly`; it changes no answer and does not advance the item. An unclear confirmation retains its original option words separately. Existing safety rules inspect the raw unmatched words and can pause routine questions immediately. This does not introduce new crisis criteria. Unknown/declined/skipped items retain the existing unscored state and complete-only arithmetic. A control confirmation during already-heard patient speech first drains that utterance: exact Yes confirms, No retries, and narrative/crisis words remain unscored and safety-checked. A control confirmation with no patient utterance can save directly. Stopping or switching to text before confirmation retains the unsent original candidate in the composer and writes no score. Capture, item/revision/session, generation, no-duplicate-save and metadata-tail guards remain in place.

To exercise the mechanics after separately authorized operator speech enablement: open a synthetic first intake; enter voice through Use voice, transcription consent and Start voice conversation; reach a PHQ item; say an exact displayed label, then Yes; verify the next item and separate saved sources. Repeat with Retry, vague speech, explicit stop/text switch and an existing crisis fixture during confirmation. Verify that omitted confirmation and skipped items never produce scores. No separate frontend flag or provider default was enabled by this slice.
