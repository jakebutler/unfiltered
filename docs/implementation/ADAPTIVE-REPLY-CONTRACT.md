# Adaptive useful reply and provisional draft contract

2026-10-10. **Engineering candidate for root review; isolated stream scaffold implemented offline, no app integration, inference or activation.** A20 remains failed; adaptive runtime remains OFF. Existing natural text/voice, seven scenarios, clinical content, DO-only reasoning and the single final confirmation remain required.

Use **one bounded streaming response**: an early locally constrained action, followed by source-linked provisional structured capture. This is a candidate to qualify, not a claim that streaming improves the existing latency distribution. Machine extraction can be a useful provisional patient-report representation under an empirically qualified policy. Neither exact quotation nor final patient confirmation establishes perfect extraction or clinical truth.

## One response, two committed packets

New candidate protocol: `adaptive-reply-draft-v1`. Keep the existing pinned DO Qwen route, transport endpoint, durable spend claim and max-output/input/body limits. Never dispatch a second broad extraction/repair call for the turn. The provider receives the entire current source, required context, current displayed prompt, directly scoped answers, separately labeled proposals, and a local action/target/source manifest; it receives no persistence identity or clinical tools.

```ts
type ReplyDraftWire = {
  advance: {
    actionId: string; // one locally issued probe, clarification or approved reply
    controls: ProposedAct[]; // max 4: source-bound move-on/topic-switch/question only
    defer: { targetId: string; evidence: SourceAddress[] }[]; // max 4
    // Defers redundant questioning only; no value, readiness or applicability credit.
  };
  draft: {
    claims: ProposedClaim[]; // max 32, declared target/type, exact value/support source
    acts: ProposedAct[];    // max 4, existing topic-switch/refusal/question semantics
    residual: { evidence: SourceAddress[]; reason: GapReason }[]; // max 8
    sourceDisposition: 'represented' | 'partially-represented';
  };
};
```

The isolated scaffold now defines exact `SourceAddress`, `ProposedClaim` and `ProposedAct` shapes in `packages/clinic-api/src/adaptive-reply.ts`: a source address is `{statementId,quote}`; a claim is `{targetId,state,value,valueEvidence,evidence,scope:{subject,entity,period,predicate},correctsSourceIds}`; an act is `{kind,targetTopicId,replyId,evidence}`. Its first compatibility manifest deliberately issues scalar targets/local probes only. Collection identities, clinical replies and full semantic admission remain future integration work, not qualified by this compatibility probe. These are **model claims to validate and qualify**, not proof supplied by the model. Required clinical meaning does not become optional because the packet is small. Overflow, omitted declarations, missing context or truncated output retain source/gaps; no capacity-based complete label.

Request an object with `advance` first and `draft` second. Stream decoding first validates provider event framing, identity/model, UTF-8, byte/time/token limits and a complete syntactically closed `advance` member. Do not execute tokens, partial strings or regex-detected braces. Enforce member order and one occurrence; reject duplicate keys or malformed prefix. A bounded incremental JSON tokenizer is required. Native schema plus stream/order behavior for this model is an **unqualified compatibility assumption**; if unsupported, this exact candidate stops. Do not silently downgrade the schema, use free prose/NDJSON, or call another route.

Validate and durably save the advance result before displaying/speaking it. The server resolves exact local copy. It cannot depend on claims that arrive later:

- Re-evaluate against current applicable/stopped topics and already supported direct/proposed answers. An action is one legitimate remaining gap probe or specific neutral ambiguity clarification, not an acknowledgement.
- Validate source-bound interruption controls before that eligibility check. A new explicit skip/move-on must stop the topic in the advance commit, not wait for the capture tail; an early question on that refused topic is invalid. Existing immediate safety interruption still runs at source acceptance before inference. Tail acts cannot undo the earlier stop or silently reopen it.
- Early `defer` is tentative interview coverage, source-linked and evaluated by the same versioned admission policy. It cannot activate a clinical branch, satisfy a required slot, invent an old-reading trigger, close a list or remove residual source. This permits skipping a duplicate height question while the rest of the measured-weight draft arrives. A rejected/ambiguous defer has no authority.
- Offer only actions whose preconditions can be established at this stage. For example, already established diabetes may permit a missing DM probe; a newly nominated/uncertain condition cannot. A neutral source clarification can ask what the patient was told without asserting a diagnosis. If no safe useful action exists, use review/partial/resume/help and record a **useful-reply failure**, not a latency pass.
- The server may select another eligible local action after a rejected nomination, once, without another provider call. It must not ask a target the advance packet has legitimately deferred. Later capture cannot retroactively justify the early action or retract it by changing the current question.

Continue decoding the same response. Only a complete valid `draft` plus the accepted terminal finish signal can commit structured candidates. Do not expose a half-decoded medicine dose/state or equate EOF, a disconnected browser or missing usage with success. Emit browser events for `advance-saved`, `draft-saved`, and truthful failure/status; these are server projections, not raw provider tokens. If capture fails after a useful advance, retain that reply and mark the source/capture gap. Unknown provider execution is never retried. Preserve available request/model/usage/finish receipts and charge the original reservation; missing final usage remains unknown.

The advance packet is an independently validated local action commit, not a declaration that the full provider result is valid. A later malformed/duplicate member or truncation fails capture. Remove that turn's early defer authority for future scheduling, keep its residual source visible, and preserve the already displayed current question rather than replacing it asynchronously. Report the partial operation; never describe it as a successful extraction.

## Admission, useful draft and completeness

Keep five distinct objects: **original source → proposed representation → direct patient correction → confirmed version → attributed clinician review**. `Draft.topics` holds directly scoped patient answers (including exact instrument choices and explicit edits). `Draft.adaptive.provisional` holds admitted proposals, conflict/supersession metadata and source accounting. “Proposed” remains visible until the final confirmed version, with exact original quote beside each meaningful detail. Optional early inspection/editing adds no attestation gate.

Use a versioned `provisional-context-v1` admission policy for this candidate, rather than claiming V7’s closed grammar accepts arbitrary speech. It has two boundaries:

1. **Mechanical/authority rejection:** exact original source/unique address, valid target/type/unit, no invented patient/entity/date/year, complete supplied temporal expression, valid collection identity/correction target, no assistant text or incompatible state/value, no scores/treatment/readiness selected by model. The known A20 cross-role uncertainty and cropped-date failures, transferred other-person states, unsupported branch anchors and correction conflicts remain required fail-closed adversarial checks. A rejected candidate and dependents remain visible gaps; final confirmation cannot rehabilitate them. Reuse existing guards where applicable, preserving the V7 grammar and historical losses as a separate protocol, not expanding it into the new general interpreter.
2. **Empirical patient-report extraction:** natural ownership/qualifier/coordination/period interpretation is model-proposed and tested against independently labeled whole-source meanings. It is not mathematically proven by the checks above. A candidate must preserve G3’s separate portion/additions unknowns and natural temporal variants as valid scoped meanings, or honestly abstain and count the capture loss. A model assertion of scope or `sourceDisposition` does not establish accuracy; their reliability must be qualified at the pinned revision. Unsupported associations detected by policy are rejected before presentation as supported detail. No provider confidence threshold substitutes for that evaluation.

`interviewTopics` overlays nonconflicting admitted proposed details and validated early defers for scheduling. It can defer a redundant question while capture is pending. `assessedTopics` includes only direct answers and fully admitted capture, excludes early defers/conflicts/rejections, and evaluates the unchanged clinical minimums. Before confirmation these are proposed intake minimums, not final clinical readiness or verified diagnoses. After confirmation they are patient-confirmed reports, still not clinician verification or treatment authority.

Every saved turn begins **unprocessed** in a server-created source inventory. Capture can mark it represented under the qualified extraction policy when all proposed source meanings are dispositioned, required mechanical coverage checks pass and no residual remains. Character/span coverage is a useful omission alarm, **not a semantic-completeness proof**. Keep full source beside its associations and retain uncovered/residual clauses, questions, cross-topic concerns, contradictions and unknown speech as explicit items. Do not rely solely on provider `residual` output or hide unprocessed concerns in a transcript. Independent qualification must inspect whole input, including meanings the model never nominated.

Do not hold every natural utterance unresolved forever or require field re-entry to close it. Equally, do not automatically declare it fully captured because a quote touched every character. A represented disposition is an empirically qualified extraction assessment with a recorded policy revision and measurable error rate. Incomplete/unknown/declined minimums, residual interpretation conflicts and relevant unprocessed source keep the intake partial; a partial confirmed handoff remains sendable. Record capture error and clinical minimum assessment separately. A stated “99%” target needs a declared meaning-level denominator and independent counts/uncertainty; it is neither a guarantee nor evidence from a tiny sample.

Positive clinical applicability uses a positively scoped patient self-report admitted under the policy; family history, medication identity and tentative coverage do not open DM. Uncertain diagnosis gets the approved clarification. Q04 preserves measured versus estimated values and full approximate timing; no invented numerical staleness cutoff. PHQ-4 stays exact stem/items/options, explicit choices and complete-only scoring outside extraction. Speech uncertainty, important amounts/negation and refusal retain their reviewed handling; summary confirmation never relabels recognized words as an exact transcript.

## Tail, correction and version safety

Minimal state additions: per-operation `replyStatus/captureStatus`, reply authority bound to `promptEpoch`, source-specific capture binding, `contentEpoch`, and per-target edit generations; ledger entries carry source, operation, policy revision, proposed detail/provenance, status and residuals. Strictly validate these optional versioned additions in `store.ts`. Keep old drafts/receipts unchanged; do not retroactively mark historical operations represented.

Capture binds immutable source text/digest, dispatched context/manifest digest and the target generations seen at dispatch. This intentionally replaces the current requirement that the *whole current draft* still equal the old snapshot before any result can apply. The dispatched context is retained as audit input; context changes do not widen what the old packet can claim. Reply application keeps the stricter current-question/epoch check.

The early reply may allow the next turn while the first response’s tail is pending. Permit one processing capture tail and one newly accepted source awaiting dispatch. Keep actual provider concurrency/spend limits unchanged: source saving is not authority to release an unknown reservation. Queue dispatch only after an acknowledged claim/admission; a status GET never starts inference. If queue/tail waiting prevents useful latency, count the failure. Server processing must own the bounded stream independently of UI rendering; disconnect/deadline loss leaves an unresolved attempt, not a new request on resume.

Capture application differs from current whole-draft replacement:

- It appends only that operation’s admitted source-linked proposals to the ledger by CAS. It never replaces `Draft.topics`, reselects dialogue, changes the active question, clears the composer or starts audio.
- Check source/binding, attempt and policy identity; compare each affected target’s edit generation. A typed/direct correction supersedes older matching proposals and derived dependents. An old tail cannot replace it. Conflicting new proposals are retained as conflicts, not last-write-wins values.
- A newer question can retire old **reply** authority without losing valid source-specific capture. New source/context cannot be treated as input the older operation saw. Do not recompute old proposals from changed context or merge collection entities by guessed names.
- Entering final review retires all pending **capture application** authority and freezes the reviewable version; pending sources remain visible partial gaps. A tail after review/confirmation is audit/receipt only. It cannot mutate the preview or confirmed content. Later additions require an explicit reopened/amendment draft.
- CAS uncertainty uses exact result/status readback, never a provider retry. Source-save replay uses the same request ID/fingerprint; an uncertain accepted source is not re-narrated or duplicated.

Add `/api/clinic/corrections` with request ID/revision, explicit topic/path and existing answer/edit fields. Factor `fieldAt/parseGuidedValue/applyGuidedAnswer` and source append out of `conversation.turn`; preserve adaptive mode and conversational prompt. Append correction lineage, supersede matching proposals, retain originals. A transcript edit appends corrected source rather than rewriting recognized speech. Unscoped/ambiguous natural corrections remain unresolved until appropriately clarified; no compulsory field-by-field review.

UI tickets must distinguish reply, capture and status events. Merge capture into answer/source views only. Existing UI/voice generations still reject stale reply/audio; scope capture/playback to prompt/content generations, so audit-only revisions cannot interrupt or restart voice. No event replaces unsent text, focus, current question or a saved correction. On unavailable interpretation offer explicit partial/resume/help or patient-selected guided recovery; never silently downgrade the accepted experience.

## Confirmation, persistence and staff work

One final confirmation freezes direct answers, admitted proposals with their attribution, clinical minimum assessment, source/residual inventory and corrections. Opening review or continuing is not acceptance. `/confirm` checks revision/digest and actual reviewed content; only confirmation time may change. Rejected claims stay rejected, partial stays partial and all underlying channels remain unchanged. Delivery/reconciliation/amendments keep the existing stable identities and no-duplicate-send behavior.

The strict `Submission` schema currently has no representation metadata and disallows answers for unknown questions. Add optional versioned `representationReview` to `clinical-core/domain.ts`, validate references/limits and bind it into the canonical submission digest. Store it in the existing clinical source DocumentReference component in `fhir.ts`; existing readback verifies the exact expected component. Do not invent an “interpretation” clinical questionnaire item. Keep metadata absent in historical submissions, preserving their digests/components. Frozen patient/staff projections read this metadata rather than mutable operations.

RD and medical staff get the complete confirmed representation, residual wording and correction lineage; clinician review remains a separately attributed act. Source-only medical concerns retain clinical work. Admin continues through allowlisted typed logistics with source IDs removed: no mixed raw utterance, proposed clinical claim or source inventory. Administrative resolution cannot close medical/RD work or imply external care.

## Small staged change and qualification boundary

**Isolated first slice implemented:** new `adaptive-reply.ts` for the bounded action-first/draft wire, separate `clinical-core/digitalocean-stream.ts`, `streaming-transport.ts` and `action-first-object.ts`; `requestJson` and the existing adapter remain unchanged. Extend `types.ts/store.ts`, `adaptive-session.ts`, `dialogue.ts`, `conversation.ts/interpretation-review.ts` and handler/contracts for the two commits, corrections and frozen metadata. Adapt `AdaptiveViews/PatientApp/useAdaptiveConversation/adaptive-state/voice-conversation` to separate events. Extend `domain/fhir/handoffs` only for digest-bound review metadata and clinical projections. Preserve old extraction protocols, V7 grammar, sources and receipts. No default activation.

1. **Offline before spend:** injected chunked streams demonstrate usable advance before tail, malformed/truncated/duplicate packets, provider identity/finish handling, single attempt/unknown receipt, new-turn queue, racing corrections, CAS ambiguity, review/confirmation freeze, resume, exact PHQ and admin/clinical isolation. Existing A20 wrong ownership/date output must reject; natural temporal/G3 meanings must survive or retain counted losses. Independently review whole-source accounting and whether early defer/probes are valid before later capture exists. Tests must exercise meaningful safety and continuity, not merely schema mirroring.
2. **Fixed separately authorized provider candidate:** one pinned existing DO Qwen route with fixed schema/guidance/policy/source fingerprints, no sweep/fallback/repair/retry. First resolve stream/native-schema/action-order compatibility; stop on failure. Measure dispatch→headers→first complete advance→advance validation/save→first usable text/audio→capture terminal/validation/save. Keep raw receipt/unknown usage; compare independently labeled semantic ownership, omissions, false representation closure, abstention, duplicate probes and correction burden. The current document makes no provider call.
3. **Acceptance before adaptive default:** independent full-source meaning review and all seven rendered mobile/desktop text/voice/switch/resume/staff journeys. Preserve the existing p95 ≤5-second end-of-utterance→first usable text/audio target, including endpointing/STT/durability/admission/DO/validation/save/TTS. At least 20 successful representative turns per declared class, with failures reported, is the existing latency floor, not enough to establish a 99% semantic claim. Report semantic numerator/denominator and uncertainty independently, plus total turns/clarifications/corrections/source openings and completion/abandonment time. Zero mandatory topic/field attestations beyond the approved final confirmation; exact instrument choices remain their specific approved acts.

**Stop conditions:** unsupported stream/schema ordering; early action needs unreceived extraction or opens an unsupported branch; adversarial ownership/date/negation/correction failure; hidden source omission/false closure; dominant partial/duplicate-probe/field-re-entry burden; stale tail changes question/audio/correction/version; or failed useful latency. A technically valid stream or final confirmation does not override a failure. Internal schema/policy qualification needs root review, not a new whole-plan user gate. A demonstrated change to clinical content, mandatory attestation, provider/scope, latency target or the adaptive experience requires targeted Jake review with the concrete tradeoff.
